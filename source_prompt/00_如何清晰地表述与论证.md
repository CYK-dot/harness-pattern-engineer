# 如何清晰地表述与论证

> **何时读我**：动笔写任何一段正文之前；或写完自查时。

---

## 1. 诉求与第一性

### 1.1 两条硬要求

本模式管两件事：**正文一律用书面语**；**每一节都要有论点与论据**。

第一条保证正文离开写作现场仍然读得懂；第二条保证它经得起追问。两条都不达标时，文档就退化成"作者说了算"。

先看第二条。一段文字读起来通顺，不等于它能被追问。读者若只能选择"信"或"不信"，这段话就没有完成任务——它把判断的责任推给了读者。

同一件事，两种写法：

> 反例："取情形，不取解法。"
>
> 正例："名字取自实现，等实现换代，就没人再认得它；取自情形，情形不变，名字一直可用。所以名字要对着情形起。"

反例是一句命令，读者只能照做，或者不做。正例给了依据，读者可以自己核对，也可以指出其中哪一步不成立。

### 1.2 两种翻车

**语域错配。** 把讨论时的语言搬进正文。讨论是即时的、有上下文的：语气、前一句、双方共同的经历都在分担表达。正文是持久的、没有上下文的，只剩字。讨论里那些"看它站不站得住""接住这四问"，离开当时的对话就不知所云。

**论证缺失。** 只有主张，没有依据。读者能看懂每个词，却不知道凭什么要接受它。

两种翻车的后果相同：文档退化成"作者说了算"。

### 1.3 第一性

> **让正文离开写作现场仍然成立：读者不必信任作者，也能自己把结论重推一遍。**

它接在《如何写一份模式》的"终"上：认知要被积累，前提是它经得起重推——不能被重推的东西，换一个人就得重新相信一遍。

### 1.4 边界

本模式只管一段正文怎么写。一份模式怎么组织，见《如何写一份模式》；一套工程怎么组织，见《如何写一份认知工程》。

## 2. 效果

| 效果 | 可观察的信号 |
|---|---|
| 读者不必信任作者，也能自己重推 | 读者能指着某一步说"这里我不认同"，而不是只能说"我觉得不对" |
| 正文不依赖写作现场 | 一个没参与过讨论的人读下来，不会撞到"这句话在说什么" |
| 语域一次定好，不再反复 | 全文调子一致；新补的一节不需要回头重调 |

## 3. 概念与方案推导

### 3.1 概念

| 概念 | 含义 |
|---|---|
| 论点 | 一段话要读者接受的那个判断。 |
| 论据 | 支撑论点的材料：事实、例子、引用、数据。 |
| 直引与转述 | 直引逐字照抄，须可核对到原文；转述用作者自己的话复述意思，只须不走样。两者都要注明出处，都不许凭记忆编造。 |
| 保证 | 把论据连到论点上的那条推理。它不写出来，推导就有跳跃。 |
| 限定 | 论点成立的范围（"通常""在这个前提下"）。省掉限定，论点就成了全称判断。 |
| 反驳 | 已知的例外与不适用处。写明它，读者才不会误用。 |
| 语域 | 语言学里指按用途区分的语言变体（同一件事，因场合不同而说法不同）。讨论是一个语域，正文是另一个。 |
| 脚手架 | 作者自述构造过程的话（"本文持一个假设""下面来验证它"）。它属于讨论，不属于正文。 |

### 3.2 方案推导

**为什么用书面语。** 正文没有上下文可依赖。讨论时，语气、前一句、双方共同的经历都在分担表达；落到纸面上，这些帮手全部消失，只剩字。书面语不是"更正式"，而是**把话说全**——凡是要靠现场才成立的东西，都得补进字里。

**语域为什么会错配。** 作者落笔时，思路还停在讨论里。上一轮正在论证"这个改法对不对"，那套论证语言（假设、成立、站不站得住）便顺势进了正文。**过程与成品用了同一套词**，于是脚手架被留在了墙上。

**论证为什么能代替信任。** 论证把结论变成可核对的推导：读者复核每一步，就不必先信任作者。这也正是认知工程能被接手、被积累的前提。

## 4. 实操与评判标准

### 4.1 表述用书面语，语域一次定好

正文的语域只有一个：**向一个没有上下文的读者讲清一件事**。

三条禁令，都能直接核对：

- 不用设问句起头。把"那该怎么办？"改成陈述。
- 不用第二人称。把"你会问……"改成对事的陈述。
- 不用靠现场才成立的比喻与口语动词（撑破、掂量、接住这类）。

《风格的要素》里有一条原则，叫"删去不必要的词"（Omit needless words）：有力的写作是简洁的。书面语的克制，首先体现在不写多余的字。

还有一条针对脚手架的判据：**正文里凡是句子在讲"我这份文档如何组织、这个说法成不成立、上面下面怎么推"，都是脚手架，删掉。**

> 脚手架："本模式持一个假设：……下面用它来检验。"
>
> 正文："人与AI助手在解决问题时，通常依次考虑四件事：……"

### 4.2 每一节先立论点，再用论据支撑

一节的骨架是三段：论点、论据、判据。论点写在最前；小标题最好就写成结论，读者扫一眼便知这一节要主张什么。

论据分两类，各有适用场合：

- **举例**：用正例与反例对照。适合说明"什么是合格的、什么是不合格的"。
- **引用**：给出经典出处。适合说明"这条做法不是我发明的，它有来历"。

**引用必须可证实。** 每一条引用都要能指认到具体出处（书、篇，必要时到页）。记不清的，要么去核实，要么改用转述并注明出处，要么不用——**不许把记不清的话写成引文**。没有把握时保持沉默，比编一条体面的引用更负责。

> 举例："效果必须配信号。"
> 反例："沟通成本降低。"——无从判断。
> 正例："同类判断第二次出现时，有人直接引用模式名。"——出现与否，一眼可见。
>
> 引用：效果为什么要落到信号，《重构》给的理由是——没有能立刻验证的手段，任何改动都只是赌。

### 4.3 论点不清与推导有漏，都表现为"五缺一"

一段可信的话有五个部件：论点、论据、保证、限定、反驳。缺哪一个，就露出哪一种病：

| 缺 | 症状 | 后果 |
|---|---|---|
| 论据 | 只有主张 | 读者只能信或不信 |
| 保证 | 论据与论点之间跳跃 | 每一步都看懂了，合起来不知凭什么 |
| 限定 | 全称判断（"总是""必须"） | 一个反例即可推翻 |
| 反驳 | 不提例外 | 读者在边界外误用 |
| 论点 | 材料堆在一起，没有主张 | 读完不知道这段要说什么 |

这张表来自论证研究里的一个经典框架：Toulmin 在《论证的使用》（1958）第三章"论证的布局"中，把论证拆成主张、依据、正当理由、支撑、限定与反驳六项。其中"支撑"是支撑"正当理由"的材料，本模式把它并入论据，于是得到五项，依次为：论点、论据、保证、限定、反驳。诊断时不必评判文采，只需找缺了哪一项。

### 4.4 修复：缺什么补什么

| 缺 | 补法 | 本工程的实例 |
|---|---|---|
| 论据 | 找一个已发生的例子，或一个可核对的出处 | "效果必须可观察"补上了《重构》"先有可靠的测试" |
| 保证 | 把"所以"之前的那一步写出来 | 四类组成的关系补上了"前一件事的结论，决定后一件事是否值得考虑" |
| 限定 | 降级为"通常""在……前提下" | "依次考虑的总是四件事"改为"通常依次考虑四件事" |
| 反驳 | 写明例外与不适用处 | "若本模式不覆盖某些情形，一并写明" |
| 论点 | 给小节写一句结论式标题 | "4.1 好的诉求与第一性，读者能认出，漂移能查住" |

补完这五项，一段话就从"作者说了算"变成"读者可以自己复核"。

### 4.5 公共评判标准

一段正文写完，按下面五条过一遍：

- **语域**：有没有设问句起头？有没有第二人称？有没有离开上下文就不成立的比喻？
- **脚手架**：有没有句子在讲这份文档自己？
- **论点**：每一节能指认出那句要读者接受的话吗？
- **论据**：每一节都配了举例或引用吗？引用都能指认到出处吗？
- **限定与反驳**：全称判断都降级了吗？例外写了吗？
