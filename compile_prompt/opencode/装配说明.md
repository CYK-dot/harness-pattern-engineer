# opencode 装配说明

你是运行在 opencode 上的 LLM。本文件指导你把 `source_prompt/` 装配成一个可用的 agent 与若干技能，全程由你自主完成。

## 目标

产出一个 opencode agent："模式工程师"。它承接认知工程的撰写、修改与评审，产出符合 `source_prompt/` 三篇规范的文档与模式。

## 输入

- `source_prompt/00_如何清晰地表述与论证.md`——一段正文怎么写；
- `source_prompt/01_如何写一份模式.md`——一份模式怎么组织；
- `source_prompt/02_如何编写一份认知工程.md`——一套工程怎么分层；
- `source_prompt/模式模板.md`——填空骨架；
- `产物定义.md`（本目录）——产物的形态与不变量；
- `验收.md`（本目录）——验收方式。

## 内容归属

按 `source_prompt/02_如何编写一份认知工程.md` 的 4.2 表分派，本工程的结果是：

| 源内容 | 落到 |
|---|---|
| 角色与铁律 | agent 的 system prompt |
| 三篇正文 | 三个技能，各自的 `description` 取自该篇的"何时读我" |
| `模式模板.md` | `如何写一份模式` 技能目录下的附带文件，按需读取 |

三篇都不进 system prompt：它们体量大于"最小高信号"，且都只在特定场合需要。

## 步骤

1. 读 `source_prompt/` 三篇，建立整体理解：各篇的诉求、四类组成与判据。
2. 生成 `build/opencode/agents/pattern-engineer.md`：YAML frontmatter（`description`、`mode`、`permission`）加 system prompt（角色、铁律、工具使用原则），按"最小高信号"改写。名称一律用拉丁小写连字符（见 `产物定义.md`）。
3. 生成三个技能，放 `build/opencode/skills/<name>/SKILL.md`，每个含 `name` 与 `description`；`description` 写明触发条件。
4. 把 `模式模板.md` 复制到 `如何写一份模式` 技能目录下，作为附带文件。
5. 生成 `build/opencode/使用指引.md`：安装、卸载、更新。产物默认不安装，只停留在 `build/` 下。
6. 按 `验收.md` 跑一轮无上下文对照实验，报告结果。

## 约束

- 产物只服务机器，不必人类可读。允许激进取舍，但不得丢失判据、限定与出处。
- 不修改 `source_prompt/`；产物一律落在 `build/` 下。
- 发现源本身有问题，改源，不就地改产物。
