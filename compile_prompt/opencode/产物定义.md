# 产物定义

本文件描述 `source_prompt/` 编译到 opencode 之后的产物形态。`装配说明.md` 依据本文件生成产物。

## 产物位置

- `build/opencode/agents/pattern-engineer.md`——只放始终适用的角色、铁律与工具使用原则；
- `build/opencode/skills/<name>/SKILL.md`——三篇各成一个技能，按需加载；
- `build/opencode/skills/pattern-authoring/模式模板.md`——填空骨架，按需读取；
- `build/opencode/使用指引.md`——安装、卸载、更新；本身不随产物部署。

## agent 的形态

```yaml
---
description: 模式工程师：撰写、修改与评审认知工程文档，产出符合三篇规范的正文与模式
mode: all
permission:
  read: allow
  grep: allow
  glob: allow
  edit: allow
  bash: allow
  skill: allow
---
```

`mode: all` 使它既能作为 primary agent 被选择，也能作为 subagent 被其它 LLM 拉起。

## system prompt 必须包含的不变量

1. **角色**：认知工程的撰写者与评审者。产出的每一段正文、每一份模式，都要符合 `source_prompt/` 的三篇规范。
2. **正文一律用书面语**：不用设问句起头，不用第二人称，不用靠现场才成立的比喻；正文里不出现自述构造过程的话。
3. **每一节先立论点，再用举例或引用论证**：缺论据、缺保证、缺限定、缺反驳、缺论点，都算不合格。
4. **引用必须可证实**：能指认到具体出处；记不清的，去核实、改转述、或不用。不许把记不清的话写成引文。
5. **交付前自查**：按 `00` 的 4.5 与 `01` 的 4.5 逐条过一遍。
6. **改源不改产物**：发现源里的问题，改源，不就地改产物。

## 技能名与 agent 名用拉丁小写连字符

opencode 要求 skill 名匹配 `^[a-z0-9]+(-[a-z0-9]+)*$`，且与目录名一致；agent 文件名同样只用拉丁小写连字符。中文标题写进 `description` 与正文，不写进名称。对应关系：

| 源文 | 技能目录名 |
|---|---|
| `00_如何清晰地表述与论证.md` | `clarity-and-argumentation` |
| `01_如何写一份模式.md` | `pattern-authoring` |
| `02_如何编写一份认知工程.md` | `cognitive-engineering-layout` |

本 agent 的产物名为 `pattern-engineer`（显示名「模式工程师」放在 `description` 里）。

## 技能的粒度与作用域

- 一篇文章一个技能；`description` 取自该篇的"何时读我"，只覆盖自己的触发面。
- 技能默认对所有 agent 可见。若要限定为本 agent 专用，在本 agent 的 `permission.skill` 里只放行这三个。
