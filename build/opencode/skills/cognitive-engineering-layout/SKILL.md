# 如何编写一份认知工程

> **何时读我**：要新建一套认知工程，或要调整它的目录与分层时。

---

## 1. 诉求与第一性

### 1.1 知识散在对话里，就没有唯一事实源

一次讨论产出的结论，如果不落进一个固定的地方，它就散在对话记录里。换个会话、换个人、换个模型接手，谁也不知道哪一份说法是真的。

同一件事，两种结局：

> 反例：结论留在对话里，产物就地手改。下次重编，手改的部分被覆盖；再下一轮，产物与源各说各话。
>
> 正例：结论落进源，产物由源生成。要改就回源改，重编一次，两边重新一致。

反例不是"不认真"，而是**没有给出唯一事实源**；只要有两处都能被改，分歧迟早出现。

### 1.2 三种事故

- **重复件**：同一份知识在两处各存一份，两边各自演进，谁也说不清哪份有效。
- **产物被手改**：产物是可再生的。手改一次，它就与源分叉；下次构建要么覆盖改动，要么让分叉永久保留。
- **换平台重建**：平台一变，组织方式全部推倒重来，认知工程成了易耗品。

### 1.3 第一性

> **让知识只写一遍，平台各取所需。**

它接在《如何写一份模式》与《如何清晰地表述与论证》的"终"上：那两篇保证一份认知**写得好、讲得清**；这一篇保证它**放得住、搬得动**。

### 1.4 边界

本模式不覆盖：一份模式内部怎么写（见《如何写一份模式》）；一段正文怎么写（见《如何清晰地表述与论证》）。它只管这些文档放在哪、怎么分层、怎么变成产物。

## 2. 效果

| 效果 | 可观察的信号 |
|---|---|
| 同一件事只有一处说法 | 发现两处不一致时，能立刻指出哪一处是源、哪一处是产物 |
| 换平台不动源 | 新增一个平台，只新增一个编译子目录；源的改动记录里没有它 |
| 产物可以放心重编 | 把产物删掉重新生成，结果一致 |
| 认知可以积累 | 新的结论落进源，而不是落进某次对话或某个平台的产物 |

## 3. 概念与方案推导

### 3.1 概念

| 概念 | 含义 |
|---|---|
| 源 | 平台无关的认知，人机可读，是唯一事实源。 |
| 编译 | 把源装配到某个平台的过程与规则。 |
| 产物 | 某平台可直接部署的形态，只服务机器。 |
| 改源不改产物 | 产物是编译结果；要改就回源改，然后重编。 |
| 两条消费路径 | 直接读源（小规模、探索期、人也在场），或读产物（稳定、高频、需要路由与按需加载）。 |
| 内容归属 | 同一份知识落到不同载体：提示词、技能、工具、子代理。 |

### 3.2 方案推导

**为什么要分三层。** 三类东西的变化速度不同：源讲的是"什么算对"，慢变；编译讲的是"装到哪、用什么形式"，跟着平台变；产物跟着工具变。把慢变的与快变的分开，平台更替就只影响后两层。这与《如何写一份模式》里"越靠近目的越稳定"是同一条线。

Parnas 在 1972 年那篇讲模块分解的论文里给出了这一思路的经典判据：分解应当依据**信息隐藏**——把可能变化的东西关在模块内部，只把稳定的部分暴露出来。

**为什么源要人机可读。** 源本身就可以被AI助手直接读，开销极低。编译的目的不是"让AI读懂"，而是规模、路由与稳定：读者多、需要按需加载、需要按平台定制时，产物才有价值。

**为什么产物不能手改。** 产物是可再生的。手改让它获得了一个源里没有的状态；下一次重编，这个状态要么被覆盖，要么永久留在两边，成为一份谁也说不清的差异。《程序员修炼之道》把背后的原则称为 DRY：系统中的每一条知识，都应当只有一个明确而权威的表述。

## 4. 实操与评判标准

### 4.1 三层目录按需生长，不要一次铺满

先建 `source_prompt/`，把认知写进去。`compile_prompt/` 与 `build/` 等到真有第一个平台要用时再建。

本工程本身就是这样：`source_prompt/` 已有三篇文档，另两层尚未建立——因为目前只有"直接读源"这一条路径在走。

反过来，一上来就把三层铺满，通常会得到一个空的 `build/`，和一份谁也不看的编译规则。

### 4.2 内容放哪：按触发方式分派

同一份源，不同内容该落到不同载体。判据如下：

| 维度 | 提示词 | 技能 | 工具 | 子代理 |
|---|---|---|---|---|
| 是否始终适用 | 是，每轮加载 | 否，按需 | 描述常在、结果按需 | 否，按需委派 |
| 体量 | 最小高信号 | 近乎无限（渐进披露） | 契约加示例 | 独立完整上下文 |
| 触发 | 恒定生效 | 描述语义匹配 | 模型决定调用 | 按描述委派 |
| 独立上下文 | 否 | 否 | 否 | 是，回传摘要 |
| 执行动作 | 否 | 可含脚本 | 是 | 可，且受权限限制 |

概括成一句话：**始终适用的进提示词，按需的大部头进技能，需要真实动作的进工具，会淹没主对话的进子代理。**

### 4.3 什么时候编译：先看有没有第二条消费路径

直接读源适用于小规模、探索期、人也在场；读产物适用于稳定、高频、需要路由与按需加载。

> 反例：只有一个人在用，却先建了一套编译规则——多出一层要同步的分叉，没有任何收益。
>
> 正例：读者多起来、需要按需触发之后，再补上编译层。

### 4.4 评判标准

- 换一个平台，源要改几个字？（应当为零）
- 同一件事有没有两处说法？发现不一致时，能立刻指出哪一处是源吗？
- 把产物删掉重编，结果与删除前一致吗？
