# 使用指引：把 `build/opencode/` 假安装到 opencode 全局

本目录（`build/opencode/`）是构建产物：`agents/pattern-engineer.md` 与三个技能目录（`skills/clarity-and-argumentation/`、`skills/pattern-authoring/`、`skills/cognitive-engineering-layout/`；其中 `模式模板.md` 是 `pattern-authoring` 的附带文件）。

**产物默认只停留在 `build/opencode/`，不会自动安装。** 要使用它，让 LLM「阅读 `build/opencode/`，安装或更新到全局」。安装方式是把产物以**软链接**方式放进 opencode 全局配置目录——本体仍留在 `build/opencode/`，全局目录里只是链接（"假安装"）。

本文件 `使用指引.md` 本身**不部署**（不建任何链接）。

## 目标配置目录

| 平台 | opencode 全局配置目录 |
|---|---|
| Linux / macOS | `~/.config/opencode` |
| Windows | `%USERPROFILE%\.config\opencode` |
| 本机示例 | `C:\Users\cyk_d\.config\opencode` |

需链接的两类：`agents\pattern-engineer.md`、`skills\*` 三个技能目录。链接后全局目录结构应形如：

```
<opencode配置目录>/
  agents/pattern-engineer.md           -> build/opencode/agents/pattern-engineer.md
  skills/clarity-and-argumentation     -> build/opencode/skills/clarity-and-argumentation
  skills/pattern-authoring             -> build/opencode/skills/pattern-authoring
  skills/cognitive-engineering-layout  -> build/opencode/skills/cognitive-engineering-layout
```

> 技能名与 agent 名一律用拉丁小写连字符：opencode 要求 skill 名匹配 `^[a-z0-9]+(-[a-z0-9]+)*$` 且与目录名一致。

## 安装

先确保目标目录存在。下面把 `<SRC>` 记为 `build/opencode/` 的绝对路径，`<DST>` 记为 opencode 全局配置目录。

### Linux / macOS（`ln -s`）

```sh
SRC=/path/to/harness-component-pattern-engineer/build/opencode
DST=~/.config/opencode
mkdir -p "$DST/agents" "$DST/skills"

ln -s "$SRC/agents/pattern-engineer.md" "$DST/agents/pattern-engineer.md"

# skills：逐个技能目录链接（目录用 -s，不加 -n）
for d in "$SRC"/skills/*/; do
  ln -s "$d" "$DST/skills/$(basename "$d")"
done
```

### Windows（`mklink`，需在 cmd，或管理员权限）

```bat
set SRC=C:\03_Projects\harness\harness-component-pattern-engineer\build\opencode
set DST=C:\Users\cyk_d\.config\opencode
if not exist "%DST%\agents" mkdir "%DST%\agents"
if not exist "%DST%\skills" mkdir "%DST%\skills"

mklink "%DST%\agents\pattern-engineer.md" "%SRC%\agents\pattern-engineer.md"

rem 目录用 /D，每个技能目录各一条
mklink /D "%DST%\skills\clarity-and-argumentation" "%SRC%\skills\clarity-and-argumentation"
mklink /D "%DST%\skills\pattern-authoring" "%SRC%\skills\pattern-authoring"
mklink /D "%DST%\skills\cognitive-engineering-layout" "%SRC%\skills\cognitive-engineering-layout"
```

> Windows 说明：`mklink` 创建目录链接用 `/D`，创建文件链接（默认）不加开关；两者均需开启开发者模式或以管理员运行。Git Bash 下也可直接用上面的 `ln -s` 示例，但需保证已启用符号链接权限。

## 卸载

删除全局目录中的上述**链接**即可，`build/opencode/` 本体保留不动。

### Linux / macOS

```sh
DST=~/.config/opencode
rm "$DST/agents/pattern-engineer.md"
rm "$DST/skills/clarity-and-argumentation" "$DST/skills/pattern-authoring" "$DST/skills/cognitive-engineering-layout"
```

### Windows

```bat
set DST=C:\Users\cyk_d\.config\opencode
del "%DST%\agents\pattern-engineer.md"
rmdir "%DST%\skills\clarity-and-argumentation"
rmdir "%DST%\skills\pattern-authoring"
rmdir "%DST%\skills\cognitive-engineering-layout"
```

> 删除的是链接本身；若某条命令误删了实体文件，从 `build/opencode/` 重新构建/复制即可恢复。

## 更新

因为是**软链接**：改源（`source_prompt/` → 增量构建 `build/opencode/`）后，全局立即生效，**无需重新安装**。

仅当**结构变化**——新增/删除/改名 skill 或 agent——时才需重新同步链接（补建或删除对应链接）；内容修改（改 `SKILL.md`、改 `pattern-engineer.md` 正文）不需要动全局目录。

配置在 opencode 启动时加载、不会热重载：安装、卸载、更新后需**退出并重启 opencode** 才生效。

## 验证

1. 新开一个 opencode 会话（重启加载配置）。
2. `@pattern-engineer` 在 agent 列表中可见，可作为 primary 选择、也可被委派为 subagent。
3. 三个 skills（`clarity-and-argumentation`、`pattern-authoring`、`cognitive-engineering-layout`）出现在 `skill` 工具列表，触发面命中时能按需加载。
4. 可用 `opencode debug agent pattern-engineer` 与 `opencode debug skill` 核对加载结果。
