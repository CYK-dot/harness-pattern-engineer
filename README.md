# 模式工程师

> 一个认知工程：让AI助手学会正确地思考，并撰写高质量的认知工程。

## 它要解决什么

AI助手不缺口才，缺的是**组织与论证**：知识不成体系，检索不到；话写出来读着顺，却经不起追问。

本工程把"怎么组织认知、怎么把话讲清、怎么把理讲圆"编译成AI助手可以直接消费的形态。

## 三层结构

| 目录 | 角色 | 类比 |
|---|---|---|
| `source_prompt/` | 知识源：平台无关、人机可读 | 源代码 |
| `compile_prompt/` | 编译器：把知识源装配到某个平台 | 编译规则 |
| `build/` | 产物：某平台可直接部署的 agent 与 skills | 二进制 |

`source_prompt/` 是唯一事实源。换一个平台，只新增一个编译子目录，不改知识源。这套组织方式本身的说明，见 `source_prompt/02_如何编写一份认知工程.md`。

当前进度：`source_prompt/`、`compile_prompt/`（目标 opencode）与 `build/opencode/` 已建；产物**未安装**，只停留在 `build/opencode/`，安装方式见其 `使用指引.md`。`build/` 由装配说明产出，不手写。

## 迭代纪律：改源，不改产物

1. 把 `build/` 的产物装到目标工程试用；
2. 发现问题，回到**源**修改：知识错就改 `source_prompt/`，构建规则错就改 `compile_prompt/`；**不直接改 `build/`**——它是产物，手改会在下次构建时被覆盖或走样；
3. 增量构建；
4. 重复。

## 换对话 / 换模型如何继续

先读本 README，理解三层结构与"改源不改产物"的纪律；再按 `source_prompt/README.md` 的索引读知识源。
